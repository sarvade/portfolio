## What was at stake

A new multimodal model for analyzing creator videos was launching, and it had to beat the old one on real traffic. Without metrics split by model version, "is the new one better?" becomes a question you answer a release cycle later, from anecdotes.

## What I built

The model's strategy version became a first-class key in the data. I carried it through three pipelines into two OLAP tables and the two APIs that read them, so downstream metrics could be compared old model against new on the same traffic. If that key goes missing at any hop, the split silently collapses into one blended number, so it had to survive every join, aggregation and sync in the chain.

<Callout label="The call">
  Mid-flight, I was asked to absorb algorithm-layer logic that belonged with the model team. I held the line: the data layer measures the model, it doesn't reimplement it. That kept ownership clear on both sides.
</Callout>

## Result

The model team compared the new model against the old one on real creator traffic from launch day, instead of waiting a release cycle. It shipped inside my first two months on the job.

## What I’d do differently now

- Add an automated test that the model-version key survives every hop, so a dropped column fails a build instead of silently blending the comparison.
